# CI uses Go 1.26.11

The workflow installs Go 1.26.11. Each `go.mod` stays on `go 1.25.4`, which is the minimum language version. `govulncheck` runs in its own job with `continue-on-error` and does not upgrade dependencies.

Go 1.25.4 is no longer on the current go.dev download list. A scan with Go 1.26.0 reports called standard-library vulnerabilities that Go 1.26.11 fixes. Called findings in `jackc/pgx`, `golang.org/x/text`, `golang.org/x/net`, `google.golang.org/grpc`, and `osrg/gobgp` remain, and this effort does not bump those modules.

## Considered options

- **Install Go 1.25.4 because that is the `go` line.** Rejected: the `go` line is a minimum, and that patch is outside the current stable downloads.
- **Fail the workflow on `govulncheck`.** Rejected: the third-party findings are a dependency upgrade, separate from adding tests.

## Consequences

New tests must stay within the Go 1.25 language. A later dependency upgrade can make `govulncheck` blocking.
