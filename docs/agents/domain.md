# Domain docs

## Before exploring

Read the root `GLOSSARY.md` and relevant decisions in `docs/adr/`.
If they are absent, proceed silently; domain-modeling creates them
when terms or decisions are resolved.

## Layout

This repository uses one domain context:
- `GLOSSARY.md`: shared domain vocabulary.
- `docs/adr/`: architecture decision records.

## Vocabulary and decisions

Use glossary terms when naming domain concepts in issues, proposals,
code, and tests. Note vocabulary gaps for domain-modeling.

If a proposal contradicts an ADR, identify the ADR and explain why
the decision should be reconsidered.
